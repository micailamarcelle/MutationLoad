This is a fork of the Masel Lab's forward time simulation, designed for studying questions
related to mutation load and demographic inference within population genetics. It simulates
the genomes of individuals in a population over time by splitting the genome into discrete
linkage blocks, with each linkage block containing a value that summarizes the effects of 
all of the mutations that have taken place in that part of the genome. 

In particular, this fork/branch focuses on investigating distortions in the SFS under human-plausible parameters for the purposes of Micaila's in-progress paper. All relevant files for running the simulation and analyzing its outputs are stored in the folder SFS_Distortions_Code within this repository. A useful guide to the primary files used in analysis is given below:

Figure Generation:
For Figure 1:
- Consists of two separate figures, both of which are generated via the UdSd_Scatterplot.py file. 
- Unlike many of the other files, this one does not directly require any sort of input file. Rather, I’ve taken data compiled from a large number of runs (all of which I believe should be found in the spreadsheet linked below) and copied it directly into the Python file itself, so the data is pretty hard-coded. 
- This Python file also actually generates 5 figures, each of which is saved under a .png with names given within the script. The two which are actually used are “const_sd_observed_variance.png” (used for Fig. 1A) and “VarianceInLogFitness_vs_UdSd.png” (used for Fig. 1B).
- The rest of the figures were used for prior investigations as we considered what we actually wanted this figure to cover within the paper!
For Figure 2:
- Consists of three separate figures, all of which were constructed via separate runs of the tskitAnalysis.py file (I specifically used the growth model version of the file, but which version is used should not matter for this figure, as it only involves the non-dadi aspects of the script). Personally, I would recommend commenting out the dadi portion of the script if you only need to generate the plots in this figure, just to speed things up and avoid all of the intricacies that come with getting dadi to actually run. 
- This python script should be copied into the folder corresponding to the output data of the simulation whose SFS you want to consider/generate. It then averages out the SFS’s corresponding to tskit “snapshots” that are taken throughout the run of the simulation.
- To this end, start_gen should be set to the last generation in the burn-in phase (unless you guys modify this further, this should be set to 100000), end_gen should be set to whatever the final generation of the simulation was (for my purposes, this was 250000), and tskit_freq should be set to the distance between tskit snapshots (I captured snapshots every 5000 generations– can be adjusted for simulations via global variance in the global variable header file). 
- The script also requires knowing N, L (the haploid number of linkage blocks– I used 23000), the Ud per linkage block (literally just Ud / L), and Sd (positive value). There are two options for entering this: if this script is just being run directly on HPC (i.e. not through SLURM), you can set it to take keyboard input for these values, which I found easiest to do when trying to analyze many different simulations at once. Otherwise, you can update the values in the script itself for different simulations– though this is a pain, it does allow you to run the script on SLURM, which can be good when you need a higher neutral mutation rate
- The script will then output a file titled “SFS_plus_expectations.png”, which will correspond to the type of graph displayed in Fig. 2. Again, though, the script must be run once per simulation of interest! 
For Figure 3: 
- Generated via SameNeDistortionsPlot.py, which is a script used exclusively for creating this figure
- Before using the script, you do have to do a couple things– this script requires data from two distinct runs of the simulation, and to speed things up, it essentially takes the information from the SFS plots corresponding to those runs and plots this together. Hence, tskitAnalysis.py must be run on these simulation outputs first. 
- Running tskitAnalysis.py will also produce several .txt files that are designed to allow for the transfer of plot information from a given simulation. I recommend renaming these to match the names given in the script (for example, I would change “cleanedSFS_output.txt” to “cleanedSFS_output_2_09.txt” to indicate that this corresponds to Ud = 2 and Sd = 0.09, and would adjust the reduced Ne filename to specify the actual reduced Ne. 
- For convenience, the x-axis from one of the simulations is also just used directly from a .txt file rather than repeating code, and I used the reduced Ne curve with the smaller Ne to improve the visibility of curves on the final plot. 
- Once all of the necessary .txt files are in the same folder as the Python script, you can run it, and it will generate the file “DistortionsComparisonPlot.png”, which will contain the desired figure. 
For Figure 4: 
- This figure is generated via tskitAnalysis_growth.py, particularly with the dadi functionality of the script.
- The way I have it set up, this script generates and plots the SFS, then feeds this SFS into dadi, which (as I currently have it set up) runs 20 perturbed replicates of optimizing a growth model. The actual growth model fitting corresponding to each replicate is plotted in a file named “dadi_model_fit_growth_ss2000_x.png”, and I then clean this up and plot it in my own style, outputting the resulting plot in “comp_observed_model_2000_growth_scaled_x.png”, with x corresponding to the number of the replicate in the sequence. “ss2000” and “2000” specifies that a sample size of 2000 was used when generating Fig. 4
- Hence, ultimately, generating this figure doesn’t require much more work than Fig. 2, EXCEPT when it comes to actually getting dadi to run. For one, I found that I was never able to get dadi to run directly on HPC– I always had to run it as a job with SLURM. To do this, I used the tskit_bash.sh bash file, which activates the necessary conda environment just before running the Python script. 
- The conda environment that I used for dadi_env (specified in the bash script) is copied into the file “CondaEnvironmentForDadi.txt” within GitHub. I believe that this should be sufficient to run the script on HPC, although you may have to look through the dadi documentation and play around with it. 
For Figure 5:
- Technically, this plot was generated via the dadiParameterScatterplot.py script, which is relatively bare-bones and largely hard-coded. It takes information compiled from runs of dadi on several simulations, then plots it all together on two distinct plots. To play with these a bit, I have python simply show the figures rather than saving them as .png files, and I then saved these manually to generate the figures ultimately used in the paper. 
- I also did some additional manipulations in PowerPoint, since I was relatively crunched for time when constructing this figure and ultimately found it easier than fighting matplotlib to get it to generate the figures I wanted directly. So, which the actual data is plotted by the script, the form of the figure is handmade within Powerpoint. 
- The actual data for this figure is generated via tskitAnalysis_growth.py. Specifically, for Fig. 5A, I applied this script to three distinct simulation runs: one with a Ud of 2.5, one with a Ud of 5, and one with a Ud of 10, as you can hopefully guess from the figure itself. For Fig. 5B, the script was applied to a single simulation run 4 separate times, with sample size being varied across these runs (sample sizes of 100, 500, 1000, and 2000, specifically).
- Rather than using the plots output by these runs of the script, I instead used the information spit out by dadi in the .out file corresponding to each run of the Python script. I took this data in each case from the replicate with the best consistent log likelihood (i.e. the replicate with the best log likelihood that appeared several times). The first two parameters output by dadi are the ones to pay attention to: the first corresponds to the ratio of the contemporary population size to the “ancient” population size estimated by dadi via the growth model, while the second corresponds to the scaled predicted duration of exponential growth, albeit in slightly strange units. I used the former value directly for Fig. 5A. For the latter with Fig. 5B, to convert it to the generations relevant to our simulation, I used a formula that Travis suggested: T (the second estimated parameter output by dadi) * Ne * 2.
- This data was then added to the dadiParameterScatterplot.py script and plotted! 

Python Files:
- BlockComparisonPlot.py: Used to determine whether the number of linkage blocks used within different simulations has any impact on the plotted site frequency spectrum. From the runs I did (L values are still in this .py file) no clear variation was observed. 
- CvijovicPlot.py: Uses the approach described by Cvijovic et al. to plot out the SFS curve predicted by their model relative to both the neutral curve and the scaled neutral curve for reduced Ne. Not used for final paper, but rather for developing understanding of how the equations within their model function
- dadiParameterScatterplot.py: Used for Fig. 5 within the paper. Notably, the information is hard-coded after being taken from the corresponding simulations, since I ultimately found this to be most efficient with how the simulations are set up and how I was able to apply dadi to them. 
- findfixedmutations.py: I believe that this Python file is actually from Joseph, used to look for fixed mutations in the output tree sequence. Did not use for my paper. 
- findVarianceInLogFitness.py: Very simple file, which takes in the output data from a given simulation and computes the mean variance in log fitness across all generations of that simulation, excluding values from within the burn-in phase. Initially, I also had a cap to clean off any outliers, but it shouldn’t be necessary when excluding the burn-in phase, so it’s commented out. This data is also stored directly in the spreadsheet mentioned below, so it’s (hopefully) unlikely that you’ll have much use for it. 
- getFixedMutHist.py: Again, I believe that this file is from Joseph– uses the info on fixed mutations from previous .py file and uses it to construct a CDF of deleterious effect size vs. probability of fixation. Did not use for my paper. 
- NeComparisonPlot.py: Compares a few different methods of computing Ne– namely, the formula given by Cvijovic et al. vs. the combined equation from Joseph’s paper vs. directly computing from tskit via the T2 / 2N equation. Ultimately, not used in the paper, but was useful for considering which value to ultimately take (had originally considered placing this in a supplementary, but I don’t think it would be that useful to do)
- SameNeDistortionsPlot.py: Used for directly comparing the SFS produced by differing simulations against one another to determine differences in shape/extent of distortions. Due to time constraints, it’s not the prettiest file, and is a bit on the hard-coded side of things. Requires .txt output files from the two simulations, essentially getting the data from the corresponding plots (can get these from .py file constructing those plots), then just chucks everything onto one big plot. Used to generate Fig. 3
- tskitAnalysis.py: Takes in tskit info from a given run of the simulation, generates neutral mutations, then plots the corresponding SFS relative to both neutral for N and reduced Ne. This file also contains some features that I was originally playing with, but which became redundant later on in the project, and can probably be removed– still have code for constructing Cvijovic et al. plots, computing values of Ne that we ultimately chose not to use, and an alternative cleaning method that isn’t best for the cases that we chose to focus on. Also contains the dadi code, which feeds the SFS into dadi, tries to fit a model, then compares the fit of the model to our actual SFS. Used to generate Fig. 2 and Fig. 4. (NOTE: The dadi functionality is a bit funky in one way– there are three versions of the tskitAnalysis.py file, each corresponding to one of the models we considered, rather than having a built-in option for switching between these models. Clunky, and not great for updating the base code, but I used while figuring out how to actually apply the dadi models. Would be good to update this!)
- UdSd_Scatterplot.py: Used to generate Fig. 1, along with several other plots that I considered when constructing this figure. Again, due to how the simulations were analyzed, I found it easiest to hard-code the information in and plot it directly, though it could definitely be cleaned up to pull directly from a spreadsheet containing the relevant points of information. 
- Ud_vs_Sd_Plot.py: Though this ultimately was not used in the framework of the paper, it was originally constructed in order to directly compare the SFS corresponding to varying increases in Ud vs. Sd. Ultimately, though, we didn’t find this to be a useful comparison, so it was scrapped in favor of the chosen figures.
